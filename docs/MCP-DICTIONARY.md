# MCP 数据字典

v0.3.1 取消固定“数据用途”选择。条目记录一个 MCP 能回答什么问题、参数如何填写、结果如何解释；查询方案直接勾选条目，巡检任务仍只选择方案。字典随本地 SQLite 保存、备份和迁移，无需额外记忆服务。

## 配置原生 MCP 查询

1. 在“运维管理 → MCP 数据字典”点击“发现 MCP”生成草稿，或新建条目填写工具标识后点击“读取工具参数”。
2. 查看实际参数名称、类型、必填项和说明。例如 trace_path 应使用自己的参数，不套用 Neo4j 模板；读取参数不会执行查询。
3. 填写能回答的问题、输入输出含义、关联方式、时间口径和限制。在调用参数 JSON 中填入固定值或占位符，核对生成的草稿后保存。
4. 点击“验证查询”，使用与巡检相同的工作目录和 Agent Preset，填写具体样例参数 JSON。样例需要真实可查对象，不能保留占位符。
5. 在“查询方案 → 编辑”直接勾选已验证条目，可以同时选择多个原生 MCP，无需分配到五种用途槽位。一个方案最多 20 个条目。
6. 发起新一次“立即巡检”，检查报告中的条目修订、调用记录和缺口。

新建方案和已切换为条目选择的方案只使用所选字典，不自动查询未勾选的旧 CMDB、Neo4j 或事件 MCP；明确空列表只分析告警原文。未切换的旧方案继续原内置流程，编辑其他参数不会悄悄切换；调整勾选后采用新规则。

## 参数模板

以下字段名只是示例，实际名称必须以“读取工具参数”为准：

```json
{
  "source_ip": "{{alert.srcip}}",
  "destination_ip": "{{alert.dstip}}",
  "max_hops": 8
}
```

| 占位符 | 取值 |
| --- | --- |
| `{{alert.srcip}}` / `{{alert.dstip}}` | 所选告警中的源 / 目的 IP |
| `{{alert.ip}}` | 所选告警明确提供的单个 IP |
| `{{alert.host}}` / `{{alert.title}}` | 告警资产标识 / 标题 |
| `{{alert.labels.KEY}}` | 指定标签值，将 KEY 换成实际标签名 |
| `{{window.start}}` / `{{window.end}}` | 本批窗口开始 / 结束的 Unix 毫秒 |
| `{{window.startSeconds}}` / `{{window.endSeconds}}` | Unix 秒，保留毫秒精度，可能带小数；需与工具参数类型匹配 |
| `{{window.startIso}}` / `{{window.endIso}}` | 带 UTC 时区的 ISO 时间文本 |

整项值只有一个占位符时保留原数值、布尔或数组类型；嵌入文本只能使用标量。未知变量、缺失 IP/标签或参数类型不匹配时记录缺口，不猜测默认对象。占位符不是脚本，不支持 eval、任意对象路径或命令。

AI 选择条目 ID 和本批告警 ID，插件从已保存模板生成实参；AI 不能临时传入任意 SQL、工具名或参数。原生补查和旧文档/记忆补查共用方案预算，重复条目及相同实参复用本轮结果。模型根据说明按需查询，不保证每个条目都会被调用。

## 文档与长期知识

Markdown、文本和 JSON 导入先生成草稿，保存后才写入字典；新文档不需要“用途”字段。可填写名称、工具、描述、数据对象、输入、输出、关联关系、时间口径、限制，以及“调用参数”JSON。

[原生 MCP 文档模板](../playbooks/mcp-tool-template.md)可复制填写；旧[资产字段映射模板](../playbooks/mcp-dictionary-template.md)仍兼容已有结构化 SQL 适配。

长期保存的是查法和解释规则。告警、在线状态及本次根因仍需本窗口证据。完整原文留在字典，分析只加载所选条目的有界说明。WeKnora 继续用于设备文档，MemOS 用于有依据的历史经验；本插件不自动向它们写入推测或训练模型权重。

## 验证、修订和边界

手动验证只运行一次工具调用，不提交模型 prompt、不生成巡检报告、不发送 IM。它创建名称明确的“MCP 字典验证”会话，以沿用 DSH 权限、审批和执行策略；正常巡检不额外创建验证会话。

原生工具按实际输入 schema 检查参数，读取最终可见的 JSON 对象、数组或文本，不强求资产或 Neo4j 固定字段。验证通过不等于字段业务含义或故障根因已经证实；空结果、截断和非文本内容分别记录限制。

保存修改会增加修订并重置验证。运行前核对可观测工具结构指纹，结构变化、工具不可用或失败时记录缺口，不换用别的 MCP；指纹不能识别所有未暴露的连接或数据库变化。

新批次入队冻结条目，排队、执行、历史报告及重新分析沿用原快照。被引用条目不能直接删除，复制或导入不继承其他环境的验证状态。

原生入口用于参数化查询；明显写操作、命令、任意 SQL/Cypher 和凭据参数不能通过此入口执行。工具声明和名称只是适配线索，实际调用仍遵循 DSH 策略。已有 SQL/Neo4j/检索映射模板继续兼容，编辑保留原模板；无适配能力的工具可以保存说明。多个原生条目可并列，旧自动取证模板同一环节仍只选一个，避免不明确的数据合并。
