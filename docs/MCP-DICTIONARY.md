# MCP 数据字典

从 v0.3.0 开始，“运维管理 → MCP 数据字典”独立保存查询知识和可执行模板。查询方案按用途引用字典，巡检任务只选择方案。字典随插件 SQLite 数据库保存、备份和迁移，重启或更换分析会话不会丢失；不需要新增 MemOS、向量库或后台巡检服务。

## 从已有环境开始

1. 打开 **MCP 数据字典**。初次提供资产、拓扑、窗口事件、知识库、历史经验五个待配置模板；它们尚未在你的服务器验证，不会自动接管已有巡检。
2. 点击 **发现 MCP**，查看当前 DSH 暴露的工具及参数，选择工具生成草稿。此步骤只读取工具元数据，不执行查询、不调用模型。没有匹配适配器的工具可保存为“仅保存数据说明”。
3. 填写用途、输入输出含义、数据对象、关联方式、时间口径和限制。也可以导入 Markdown、文本或 JSON 文档；先检查生成的草稿，保存后才写入字典。
4. 检查“查询模板”。它配置表名、列映射、拓扑标签或检索参数，插件据此生成限定范围的查询。文档示例见 [导入模板](../playbooks/mcp-dictionary-template.md)。
5. 保存后点击 **验证查询**，使用与巡检相同的工作目录和 Agent Preset，提供一个已知 IP、交换机对、有限设备与时间窗，或具体检索词。验证只执行样例查询，不调用模型、不生成巡检报告、不发送 IM。
6. 到 **查询方案 → 编辑**，在对应数据用途选择该条目；同一个方案可以分别引用不同 MCP 的资产、事件和拓扑条目。保存后，从巡检任务发起一次新的“立即巡检”，检查报告中的字典修订、查询耗时与缺口。

未选择字典的用途继续使用原有内置模板和用途绑定。显式选择字典后，以该字典的工具和模板为准；条目失效时记录缺口，不悄悄改查另一个 MCP。

## 应当记住哪些内容

| 字段 | 应填写的内容 |
| --- | --- |
| 名称、用途 | 例如“网络 CMDB 主机接入映射”，用于资产归一 |
| 工具 | DSH 实际暴露的完整工具名，通过发现列表选择 |
| 描述、数据对象 | 能回答什么问题，使用哪些表、图节点或知识库 |
| 输入、输出 | 参数和返回字段的业务含义、单位、空值及歧义处理 |
| 关联关系 | 主机 IP → 接入交换机名 → 拓扑节点，不混用主机 IP 和交换机管理 IP |
| 时间口径 | 当前快照或历史记录；发生、采集或入库时间；时区和时间单位 |
| 限制 | 覆盖范围、保留期、缺失数据及不能据此作出的判断 |
| 原始文档 | 完整说明的本地留档；运行时只加载相关说明的有界摘要 |
| 查询模板 | 与上述说明对应的声明式字段映射或检索参数 |

长期保存的是“查什么、怎么查、如何解释”。实时告警、在线状态、接口指标及根因结论不能因历史查询成功而当作本轮事实。资产映射仍受原有短期缓存控制；窗口事件每轮重新查询。

## 当前支持的模板

- **资产与接入映射**：PostgreSQL 表/视图及输出字段映射；至少提供 IP 和接入交换机字段。支持保留 VRF、重复 IP 和接入歧义，按本批告警的有限 IP 集合查询。
- **交换机候选路径**：Neo4j 节点标签、关系类型、交换机身份和可选状态/时间/端口属性。以已归一的交换机对查询最多 8 跳的候选路径，不把它认定为真实转发路径。
- **窗口设备事件**：最多四个 PostgreSQL 表/视图，配置设备、事件、时间、可选接口和详情列。支持时间戳、Unix 秒及毫秒；只查询相关设备和本批时间窗。
- **错误码与文档 / 已确认历史经验**：配置检索词参数、可选数量参数及知识库等固定参数。检索词由本批具体错误码或资产/路径生成，受方案补查预算限制。
- **仅保存数据说明**：记录尚无执行适配器的 MCP 用途和文档，不自动执行，也不会因导入说明而获得新查询能力。

模板是 JSON 形式的配置，不是任意 SQL/Cypher 脚本。表名和列名使用简单标识符；不同查询形态、跨表复杂 JOIN、自定义指标接口需要另行增加适配器。数据库可用视图提供所需字段，插件不会替你创建或修改视图。

固定检索参数用于知识库 ID 等范围配置，不存密码、Token 或授权头；连接凭据继续由 DSH/MCP 管理。

## 验证状态与更新

验证会创建一个名称明确的 **MCP 字典验证** 会话，以使用 DSH 的工具执行与权限策略。它不向模型提交分析提示词；每次由你点击触发，不会随半小时巡检额外创建验证会话。验证结果记录会话 ID、耗时、条数和时间，查询到的业务数据不作为长期事实写入字典。

- 有样例且返回结构通过检查：查询验证通过。仍需核对业务字段含义，工具调用成功不能证明根因或语义正确。
- 执行成功但没有返回记录：单独标明空结果，允许方案引用；没有验证返回行的结构或业务含义，不能解释为窗口内没有异常。
- 查询失败、返回格式不兼容或参数不满足：保留失败原因，需要修改后重试，不能作为新的有效引用。

编辑条目会增加修订并重置验证状态。已引用它的方案保留引用，后续新批次会明确显示待验证缺口；完成重新验证后再开始新巡检。正在排队、执行和历史报告使用入队时保存的字典快照，“重新分析”也沿用原批次快照。

运行前检查可观测工具参数结构指纹；工具结构改变时要求重新验证。这个指纹不代表能识别所有未暴露的连接地址、权限或数据库结构变化；实际查询仍检查响应并记录失败/缺口。没有定期全库扫描或每轮枚举表结构。

被查询方案引用的条目不能直接删除，需先调整方案引用。删除未被引用的条目不会影响历史报告快照。导入和复制均创建未验证草稿，不能把导出文件中的“已验证”状态直接带入另一环境。

## 与 WeKnora / MemOS 的分工

数据字典是巡检可直接读取的本地查询说明；WeKnora 可以继续提供设备手册和详细机制文档，MemOS 用于检索带依据的历史案例。此版本不自动向两者写入字典，不将每轮 AI 推测保存成已确认经验，也不训练或修改模型权重。
