# 查询方案

0.2.0 将任务的手工工具白名单替换为按用途执行的查询方案。目标是减少逐轮查表结构、猜字段、重复检索和无关查询。沿用现有 DSH Web 进程及 MCP 连接，无需再运行独立巡检服务。

## 配置入口

打开“运维管理 → 巡检任务 → 配置 → 查询方案”。每个任务独立保存方案类型、用途绑定、超时、缓存时间、补查预算和 Markdown 补充说明。

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| 方案类型 | 网络 ping | 批量资产归一、候选路径和窗口事件取证 |
| 用途绑定 | 自动识别 | 优先匹配内置适配 MCP，同优先级唯一兼容项才使用；多候选需手工指定 |
| 单次查询超时 | 15 秒 | 范围 1–60 秒，到期发出取消信号；等待 MCP 响应后记录缺口 |
| 资产映射缓存 | 300 秒 | 范围 0–3600 秒，0 关闭跨轮缓存 |
| AI 额外补查上限 | 2 次 | 范围 0–6 次，所有分批共用；固定预取不占此预算 |
| 方案补充说明 | 空 | 留空采用内置流程；可补充业务判定和停止条件 |

用途绑定选择的是“资产与窗口事件”“网络拓扑”“错误码与机制说明”“已确认历史经验”，不再逐个勾选全部工具。选择一个用途工具并不把它完整开放给模型；后端按固定查询模板或受控检索参数调用。不同 MCP 参数不兼容时不会凭空猜测调用方式，报告保留缺口。查询调用经过 DSH 的原有执行与审批策略，要求 DSH 0.2.2-rc.1 或更高的 0.2.x 版本。

## 固定取证流程

网络 ping 方案先识别实际的 ping 告警，将源/目的 IP 去重并批量查询 PostgreSQL 的资产映射。资产映射确认后，通过 Neo4j 查询两端交换机间的有界候选路径，再查本窗口内相关设备的事件。

资产查询保留映射歧义和采集时间，不能简单地取第一行作为确定资产。主机 IP 先转为接入交换机身份，不直接用主机 IP 匹配交换机管理地址。没有直连不等于没有多跳路径；候选拓扑路径不等于已确认的实际流量路径。当前映射和拓扑也不能直接证明历史窗口状态。

通用取证方案优先整理告警与可识别资产，不强行执行 ping 路径流程。混合批次中的非 ping 告警仍交给模型分析，并继续要求覆盖每个原始告警 ID；缺少专门查询模板时明确写出限制。

当前模板适配 `public.cmdb_online_ip_switch_port_current`、三张交换机事件表及 Neo4j 的 `Switch` / `CONNECTED_TO` 拓扑。MCP 可调用不代表其数据库结构一定匹配；表或字段不同会明确失败，需要修改适配模板，不能只在说明里写一个新表名。

普通 ping 默认不查询整套设备手册。知识库补查必须能从原告警中提取具体错误码，没有可定位错误码时不执行宽泛机制搜索。历史记忆补查使用本批次明确的资产标识和告警标题。检索词由插件生成，模型只能选择用途；同一用途重复请求复用本轮结果，兼容工具的结果数参数设为 3。历史结果仍需核验来源、时间与确认依据，不能因为搜索词含“已确认”就当成本次故障证据。没有接口错误/丢弃计数或时序指标工具时，应记录缺失，不能用“没有查到日志”代替链路正常结论。

固定查询限制为最多 64 个 IP、256 条资产映射、16 组端点对、128 台相关设备和 100 条窗口事件，候选路径最多 8 跳。每类固定证据最多保留 6000 字符，补查文本也限制为 6000 字符。超出数量、文本预算或日志长度时标为部分结果，不将截断解释为完整覆盖；全部原告警仍交给模型并校验告警 ID 覆盖。

## 文档怎样生效

内置方案说明可在任务中展开查看。“方案补充说明”与“报告补充要求”均随任务保存并注入本轮分析。前者解释查询目的、停止条件和证据判定；后者补充业务背景及报告表达。方案文本不会自动授予新工具或新增任意 SQL/Cypher 模板。

例如可以填写：

```markdown
仅关注告警路径上的设备与本巡检窗口。
两端资产映射有歧义时保留候选，不把不同 VRF 的相同 IP 合并。
无端口事件时记录证据不足，不扩展到无关机房和前一天日志。
历史相同告警只作为排查线索，不能沿用上一轮根因或恢复结论。
```

`playbooks/network-alert-analysis.md` 是可粘贴的示例文档，不是自动监听的服务器配置文件。修改它不会自动更改已保存任务。若新增专门查询对象或数据源，需要实现对应模板与用途适配，单靠描述表名不会执行查询。

## 缓存与耗时

资产映射使用进程内 TTL 缓存，按任务、工作区、工具与方案隔离；重启失效。失败及截断结果不缓存。缓存只保存稳定映射并保留采集时间，实时状态字段不作为跨轮证据复用。告警窗口事件、指标和本轮异常结论不跨轮复用。

报告“查询方案与耗时”显示方案版本、查询用途、工具、执行状态、耗时、结果条数、缓存命中及缺口说明，可以导出查询证据 JSON。预取阶段总耗时已包含该阶段的各项查询，AI 回复阶段还包含模型处理和额外补查；不能将这些字段重复累加，也不能把 AI 回复耗时当作纯推理时间。

模型仍可能需要时间归并证据和生成最终报告。单查询超时、额外补查预算与原有任务总超时共同限制执行。超时采用协作取消：发出取消信号后等待 MCP 退出，不强制杀掉后台数据库查询；若工具不响应取消，实际等待可能超过配置秒数。查询失败不等于无异常，最终报告仍需通过告警 ID 覆盖校验。

## 升级行为

旧 `allowedTools` 和 `maxToolCalls` 不再生效。没有查询方案的任务运行时采用默认方案；保存后写入新配置。旧配置中的业务说明保留，但不能绕过新的查询入口。旧报告保持生成时的数据，不因升级而补填取证记录。

升级后先手动运行一次已知告警，核对用途绑定、映射和候选路径、窗口事件以及耗时。没有唯一兼容 MCP 的用途会被明确标为缺失，可在任务配置中指定兼容工具。零告警继续只保存本地报告，不查询 MCP、不创建分析会话、不推送 IM。

本版不自动将 AI 推测写入 MemOS，不新增向量库，不修改用户的 DSH 模型与全局预设。已确认经验的长期写回应由独立流程维护。
