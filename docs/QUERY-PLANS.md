# 查询方案

查询方案独立管理，巡检任务只选择方案。v0.3.1 直接勾选 [MCP 数据字典](MCP-DICTIONARY.md)条目，不再分配到固定用途槽位；工具参数、能回答的问题和结果含义一起提供给本轮分析。沿用现有 DSH Web 进程及 MCP 连接，无需独立巡检服务。

## 配置入口

打开“运维管理 → 查询方案”，创建、编辑或复制一个有名称的方案，在此选择字典条目，维护超时、缓存、补查预算和 Markdown 补充说明。

然后打开“运维管理 → 巡检任务 → 配置”，在“查询方案”下拉框中选择已保存方案。任务不再包含方案的编辑表单，多个任务可以引用同一方案。告警源、周期、工作目录、报告要求和投递设置仍属于各自任务。

初次初始化提供网络 ping 与通用取证两个方案。需要不同策略时可复制现有方案再修改；复制会创建独立方案，不会改变原来的任务引用。

直接勾选本方案需要的字典，多个原生 MCP 可以并列使用；已选条目的工具、参数模板和说明生效。新方案只使用所选条目，空列表只分析告警原文。旧方案未调整勾选时保留原内置流程，切换后不再自动查询未选 MCP。字典仍在独立页面编辑。

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| 方案类型 | 网络 ping | 批量资产归一、候选路径和窗口事件取证 |
| 字典条目 | 新方案未选择 | 勾选需要的查询条目；旧方案的自动绑定仅在未切换时保留 |
| 单次查询超时 | 15 秒 | 范围 1–60 秒，到期发出取消信号；等待 MCP 响应后记录缺口 |
| 资产映射缓存 | 300 秒 | 范围 0–3600 秒，0 关闭跨轮缓存 |
| AI 额外补查上限 | 2 次 | 范围 0–6 次，所有分批共用；固定预取不占此预算 |
| 方案补充说明 | 空 | 留空采用内置流程；可补充业务判定和停止条件 |

AI 根据条目说明选择查询，并指定本批告警 ID；插件用该告警和窗口填充参数模板，AI 不直接提交任意实参。补查共用预算，相同条目及实参复用本轮结果。查询经过 DSH 原有执行与审批策略，要求 DSH 0.2.2-rc.1 或更高的 0.2.x 版本。

## 兼容旧自动取证流程

以下是旧方案和已选择旧映射模板的固定取证行为。原生 MCP 条目按自身参数调用，例如 IP 路径查询不套用 Neo4j 模板。

网络 ping 方案先识别实际的 ping 告警，将源/目的 IP 去重并批量查询 PostgreSQL 的资产映射。资产映射确认后，通过 Neo4j 查询两端交换机间的有界候选路径，再查本窗口内相关设备的事件。

资产查询保留映射歧义和采集时间，不能简单地取第一行作为确定资产。主机 IP 先转为接入交换机身份，不直接用主机 IP 匹配交换机管理地址。没有直连不等于没有多跳路径；候选拓扑路径不等于已确认的实际流量路径。当前映射和拓扑也不能直接证明历史窗口状态。

通用取证方案优先整理告警与可识别资产，不强行执行 ping 路径流程。混合批次中的非 ping 告警仍交给模型分析，并继续要求覆盖每个原始告警 ID；缺少专门查询模板时明确写出限制。

内置模板适配 `public.cmdb_online_ip_switch_port_current`、三张交换机事件表及 Neo4j 的 `Switch` / `CONNECTED_TO` 拓扑。表或字段不同，可以在数据字典中配置对应的声明式映射并验证；不同查询形态仍需增加适配器。MCP 可调用不代表数据库结构一定匹配，不能只在说明里写一个新表名。

旧知识库模板只为原告警具体错误码补查，历史模板使用本批明确资产与告警标题；兼容工具的结果数参数设为 3。原生 MCP 使用已保存参数模板及对应告警取值，仍应根据条目适用范围避免无关搜索。历史结果需核验来源、时间与确认依据，不能因为检索词含“已确认”就当成本次故障证据。没有接口指标工具时明确缺失，不能用“没有查到日志”代替链路正常结论。

固定查询限制为最多 64 个 IP、256 条资产映射、16 组端点对、128 台相关设备和 100 条窗口事件，候选路径最多 8 跳。每类固定证据最多保留 6000 字符，补查文本也限制为 6000 字符。超出数量、文本预算或日志长度时标为部分结果，不将截断解释为完整覆盖；全部原告警仍交给模型并校验告警 ID 覆盖。

## 文档怎样生效

内置步骤与“方案补充说明”在独立查询方案中维护；“报告补充要求”仍在巡检任务中维护。前者解释查询目的、停止条件和证据判定，后者补充业务背景及报告表达；执行时都会注入本轮分析。方案文本不会自动授予新工具或新增任意 SQL/Cypher 模板。

例如可以填写：

```markdown
仅关注告警路径上的设备与本巡检窗口。
两端资产映射有歧义时保留候选，不把不同 VRF 的相同 IP 合并。
无端口事件时记录证据不足，不扩展到无关机房和前一天日志。
历史相同告警只作为排查线索，不能沿用上一轮根因或恢复结论。
```

`playbooks/network-alert-analysis.md` 是可粘贴的示例文档，不是自动监听的服务器配置文件。修改它不会自动更改已保存方案；请将需要的规则粘贴到“查询方案 → 编辑 → 方案补充说明”并保存。参数化只读 MCP 可通过字典中的原生参数模板接入；直接 SQL/Cypher 仍需使用兼容的受限模板，单靠描述表名不会执行查询。

## 缓存与耗时

资产映射使用进程内 TTL 缓存，按任务、工作区、工具、方案内容、方案库及字典 ID/修订号隔离；重启失效。失败及截断结果不缓存。缓存只保存稳定映射并保留采集时间，实时状态字段不作为跨轮证据复用。告警窗口事件、指标和本轮异常结论不跨轮复用。

报告保留实际使用的方案名称、字典条目及修订号。“查询方案与耗时”显示模板版本、查询用途、工具、执行状态、耗时、结果条数、缓存命中及缺口说明，可以导出查询证据 JSON。预取阶段总耗时已包含该阶段的各项查询，AI 回复阶段还包含模型处理和额外补查；不能将这些字段重复累加，也不能把 AI 回复耗时当作纯推理时间。

模型仍可能需要时间归并证据和生成最终报告。单查询超时、额外补查预算与原有任务总超时共同限制执行。超时采用协作取消：发出取消信号后等待 MCP 退出，不强制杀掉后台数据库查询；若工具不响应取消，实际等待可能超过配置秒数。查询失败不等于无异常，最终报告仍需通过告警 ID 覆盖校验。

## 共享、修订与删除

保存已有方案时修订号递增，界面显示引用它的任务。修改影响这些任务后续新建的巡检批次；已排队或正在执行的批次使用入队时复制的方案内容、名称、字典和修订号，不会中途变更。

历史报告及“重新分析”继续使用原批次的任务/方案快照。若要验证新方案，保存方案后从任务发起新一次“立即巡检”。不能用旧报告的重新分析来验证刚修改的共享方案。

正在被任务引用的方案不能删除，包括停用的任务；先为这些任务选择其他方案再删除。已完成报告的快照不会阻止删除，也不会因删除而丢失。编辑过期修订会被拒绝，需重新打开最新方案，避免覆盖另一页面的修改。

## 升级行为

升级时将旧任务的内嵌查询配置迁移到方案库，并替换为方案引用。自定义规则、用途绑定、超时、缓存、补查预算及任务启用状态和排程保留，不重建任务或告警源。迁移持久化且可重复读取，不会每次刷新新增方案。旧白名单和原有 maxToolCalls 仍不生效。

旧报告保持原有内嵌方案，不因升级补填或重写。已经初始化后的空方案库不会自动恢复已删除的预置方案；新任务需要先建立并选择有效方案。

升级后先手动运行一次已知告警，核对选中条目、参数取值、返回证据与耗时。原生条目需读取真实工具参数并验证；未选或失效条目不会被模型调用。旧方案尚未切换时继续保留兼容绑定。零告警仍只保存本地报告，不查询 MCP、不创建分析会话、不推送 IM。

本版不自动将 AI 推测写入 MemOS，不新增向量库，不修改用户的 DSH 模型与全局预设。已确认经验的长期写回应由独立流程维护。
